# go-telemetry-pipeline

Go HTTP API for validating metric events. Kafka and PostgreSQL integration is planned.

# Running the application

Start the server with go run ./cmd/telemetry.

Check that the server is running by sending a POST request to /metrics on port 8080.

Example:
```bash
curl -v http://127.0.0.1:8080/metrics -H "Content-Type: application/json" -d "{\"id\": \"0192a5b0-6c2e-7f3a-8b4d-1e2f3a4b5c6d\", \"timestamp\": $(date +%s), \"key\": \"input_traffic\", \"value\": 0}"
```

The route expects to receive a JSON in request's body representing an event with id, timestamp, key and value.

ID is a UUIDv7 value in canonical format generated by the client and reused in retries. Timestamp is an integer representing a unix epoch time in seconds. Key is a string to identify the name of the property and value is a double precision representing the property value.

All fields are required. Timestamp must be between 7 days in the past and 5 minutes in the future, relative to the server clock (see ADR 0002). Key must not be empty, must have at most 255 characters and must not contain NUL bytes. Value accepts 0.

A valid event responds with HTTP status 200 and invalid json or valid json with invalid fields with status 400.

GET requests are not allowed and response for this request is status 405.

Currently the handler only evaluates the event. No action is dispatched to Kafka or any other service.
